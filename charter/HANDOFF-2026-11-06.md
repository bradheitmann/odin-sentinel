## 5. Team protocol (adopted and implemented)

- **Roles:** PM-ODIN (Claude) plans, dispatches, accepts and lands. OD/DEV implements. OD/QA verifies independently, always a different model family, and never fixes. Reviewers and implementers are always distinct. Seats are dispatched through `odin-say`, with a private dispatch log.
- **Charter lifecycle** (enforced by the pinned binary and hooks):
  1. a DONE list with numbered proofs, each with a reopen step and a fail-without mutant;
  2. `charter gate <slice> --dispatch` before any code;
  3. DEV in its own worktree;
  4. a cross-family QA report plus a `charter.receipt/1` (model ids);
  5. `charter freeze`, then `charter reopen --proof all`, then `charter receipt --verify-tree`;
  6. `gate --accept`; cost rows; STATE rewritten in the same change.
- **Landing:** a LOCAL merge or squash on main under the no-reply identity, then a push through the gate. Never merge on GitHub (it stamps the owner's personal email). Check identities before every push. A squash records tree equality with the accepted head. Archive-tag a branch before deleting it (one ruled PII exception).
- **Privacy:** the owner-PII rule is that no owner email, name or home path appears in tracked files, revision messages or review artifacts. A private pattern check runs before every commit. The public-surface audit and Mister Clean's public-safety audit must report 0 findings.
- **Secrets:** they come from Doppler; check names and lengths only, never values. Inspect the attestation config only through Mister Clean's read-only `attest-inspect` helper. Seats never compose Doppler commands against an attestation config. The only exception is the attester's exact signing command.
- **Judging:** Mister Clean `prepare` and `validate` run only in PM-MISTER-CLEAN's Linux judge container (no Doppler, no keys). Audit-only checks may run on the host.
