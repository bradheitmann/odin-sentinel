# charter — the contract (SPEC)

Version: `charter v1`. This document is normative: where a file, the binary, and this document disagree, the disagreement is a defect in one of them. How this version bumps is defined in [GOVERNANCE.md](GOVERNANCE.md).

## The object

A project under charter carries a `charter/` directory that makes the questions research never asks (cost, bound, proof, owner, stop) mandatory, in writing, before design, before dispatch and before "done".

## The files (normative)

| File | Required content | Enforced by |
|---|---|---|
| `charter/charter.toml` | `charter_version = "1"`; optional `spec_version` (must equal the binary's supported spec); `project`; `owner`; `[slice_zero]` description/command/`proven_on`; `[verification_budget]` qa_attempts_per_slice, repair_cycles_per_slice, review_families_required, optional `seat_evidence` (`"required"` or `"optional"`, default `"optional"`); optional `[state]`: `branch` (the state branch; unset means `main` or `master`), `max_commits_behind`, `park_allows` | `check`, `check --strict` (schema) |
| `charter/INTENT.md` | the intent card: underlying job (not symptom), beneficiary, situation, outcome, non-goals, 3 guarantees, largest uncertainty, premise check; no template bullet left valueless | `check` |
| `charter/GUARANTEES.yaml` | a list; each entry: `id`, `statement`, `owner`, `proof`, `cost_per_run`, `if_dropped`, `status`; `proven` requires proof + cost (contract layer) and every entry requires owner/proof/cost (strict layer) | `check`, `check --strict` |
| `charter/LOOPS.yaml` | a list; each entry: `id`, `where`, `trigger`, `bound`, `cost_per_trip`, `stop_condition`, `who_decides_extension`; optional integer `trips` (a loop past its bound's leading number is a strict refusal) | `check`, `check --strict` |
| `charter/STOP-RULES.md` | rules identified `S<n>`, unique, one per line | `check` (change requires an owner decision), `check --strict` (hygiene). A rule an owner decision amends (`- amends: S<n>` followed by `- text: <the rule>` in charter/owner-decisions/) must read as the newest such decision says; otherwise check refuses. |
| `charter/DONE/<slice>.md` | the numbered proof list, written before dispatch, never grown during it; each proof names a reopen step and a fail-without mutant; accepted slices carry `reopened: <run-id> <sha256>` markers | `check --strict`, `gate`, `receipt` |
| `charter/DONE-LEGACY.txt` | optional: one slice id per line (`#` comments allowed); it only shrinks from the list as first committed, and names only proof lists that existed before that commit; each listed proof list keeps the bytes it had before that commit; a listed proof list is not judged for proof form by `check --strict` and is never dispatched by `gate --dispatch` | `check`, `check --strict`, `gate --dispatch` |
| `charter/VERIFY-LEGACY.txt` | optional: one slice id per line (`#` comments allowed); it only shrinks from the list as first committed, and names only slices whose `charter/.dispatch/<slice>.json` recorded them accepted before that commit and records them accepted now; each listed proof list keeps the bytes it had before that commit; for a listed slice `gate --verify` reports a proof list changed after acceptance as a note and does not refuse, and `gate --dispatch` refuses the slice | `check`, `check --strict`, `gate --verify`, `gate --dispatch` |
| `charter/STATE.md` | leave-state: proven/not proven, last-green/last-red commands, next three bounded items, open owner decisions; a **generated block** between <!-- charter: generated by `charter state --write`; do not edit by hand --> and <!-- charter: end of generated part --> holds the recorded HEAD, the dirty files, the last-green command, how many slices landed (with the latest one's acceptance instant), one `- Open:` line per slice that is dispatched, frozen or accepted but not landed (naming its owner when the dispatch record does) and how many proof lists were never dispatched — facts a program recomputes, never judgement; `charter state --write` rewrites only that block, and migrates a file that has none without losing a line (a file whose first line starting `Proven` has only an earlier generated header — its title, `- HEAD:` lines and blank lines — above it has that header replaced by the block and keeps every other line; any other file keeps line 1, gains the block after it and loses only its first `- HEAD:` line; a file whose earlier header also carries `- Dirty files:` and `- Last-green:` lines takes the second form, so the facts those lines hold are kept); rewritten after every acceptance; on the state branch and under `check --landing`, a recorded HEAD at most 7 days old and at most `max_commits_behind` (default 20) commits behind, a note elsewhere; a `- PARKED: <UTC> charter/owner-decisions/<file>.md` line at column 0 outside a code fence suspends those two rules, refuses dispatch, and makes plain `check` refuse a staged path that is not a record | `check`, `check --strict`, `gate --dispatch`, `state` |
| `charter/owner-decisions/<date>-<slug>.md` | an owner decision; a relaxation (`relaxes: S<n>`) needs two distinct `approved_by:` signers | `check` |
| `charter/.dispatch/<slice>.{sha256,json}` | the dispatch pin: DONE hash, brief sha256, base commit, acceptance state, and for an acceptance the receipt's path and sha256 | `gate`, `check`, `land-check` |
| `charter/.freeze/<slice>.json` | the frozen bytes: head, manifest sha256, per-file hashes, the green CI run | `freeze`, `receipt --verify-tree` |
| `charter/PIN.toml` | optional: the build this repository runs, a top-level `commit = "<40-hex>"`, or `"self"` in the charter source repository only, which then also accepts HEAD or the build a top-level `hooks_commit` names; a file the hooks would read differently is refused | the installed hooks (refuse); `check --strict` (refuses a mismatched build or a refused file; plain `check` warns); `hooks status` |
| `charter/COST.jsonl` | one JSON row per cost record (schema `charter.cost/1`); never fabricated | `cost`, `check --strict` (warning) |

An acceptance's dispatch record holds `receipt_sha256` and, as `receipt`, the receipt's path when it is inside the repository, and its sha256; a receipt kept outside the repository is recorded with `receipt: null` and `receipt_kept: "outside"`, by its sha256 alone. The same holds for the `--allow-same-family` decision: `allow_same_family` when it is inside the repository, `null` with `allow_same_family_kept: "outside"` when it is not. No record this binary writes holds a path to a file outside the repository.

## The commands (normative exit codes)

Every command exits 0 on success, 1 on a typed refusal (the refusal text names the file, rule, proof, or loop), 2 on usage errors.

- `charter check [--strict] [--landing] [--pushing <ref>]…` — contract validity; strict adds schemas, proof discipline, loop bounds, rule hygiene, spec version and the declared pin; `--landing`, or a `--pushing` ref equal to `refs/heads/<state branch>`, applies the STATE age and distance rules on any branch; STATE.md's generated block is compared with a fresh generation — every line but `- HEAD:` and `- Dirty files:` must equal it, or `check` refuses with the first differing line and names `charter state --write` (a file without a block, and an empty block, are unaffected).
- `charter state --write` — regenerates STATE.md's generated block from git and the records and keeps every hand-written line: a file whose block is present has only the block rewritten; a file without one is migrated once, without losing a line — a line starting `Proven` that only an earlier generated header (a title, `- HEAD:` and blank lines) precedes keeps the earlier behaviour (the block replaces that header above it, and line 1, the `Proven` line and every line after it stay), and any other file keeps line 1, gains the block after it and loses only its first `- HEAD:` line. A file whose earlier header also carries `- Dirty files:` and `- Last-green:` lines above its first `Proven` line takes the second migration: those facts are kept as the file's own lines.
- `charter gate <slice> --dispatch [--brief <file>] [--owner <text>]` — pins the DONE hash, brief sha and base commit, and with `--owner` records the owning seat as `owner` in the dispatch record (without the flag no owner key is written); the contract must pass, the repository must not be parked, and the slice must not be on `charter/DONE-LEGACY.txt` or `charter/VERIFY-LEGACY.txt`.
- `charter gate <slice> --accept --receipt <file> [--allow-same-family <decision>]` — refuses DONE drift; a slice not yet accepted needs its freeze record and a receipt that passes `charter receipt`'s rules with an accepted verdict for this slice and whose `dispatch` and `frozen` citations equal the records; records `state: accepted` with the receipt's path when it is inside the repository, and its sha256; an accepted slice is never re-judged or rewritten; it also refuses a slice whose dispatch record is not in the frozen tip's history with the proof list it hashes, or whose first code commit on its branch predates the dispatch record, unless an owner-decision line `- retro-dispatch: <id>` names the exception, which the acceptance then records.
- `charter gate <slice> --verify [--receipt <file>]` — writes nothing; refuses DONE drift (for an accepted slice on `charter/VERIFY-LEGACY.txt`, a note), a `charter/.dispatch/<slice>.json` that exists but is not a JSON object, and, for an accepted slice, a recorded receipt whose bytes changed; with `--receipt`, needs that record and judges a pending receipt for a slice not yet accepted as `--accept` would, without accepting it.
- `charter freeze <slice>` — records the tree manifest.
- `charter land-check <range>` — every first-parent commit in the range lands as an accepted slice merge (an accepted dispatch record, a freeze record whose head is the merged tip or behind it with only that freeze file between, and a committed `qa/<slice>/receipt.json` with an accepted verdict that passes `charter receipt`'s rules, judged against the dispatch record as committed at that merge) or as a records-only commit; a slice landing whose `charter/STATE.md` hand-written part is byte-identical to the previous landing's (the nearest earlier first-parent commit with two parents, a file's block excluded) is refused, naming that commit and the slice: rewrite STATE's judgement before landing.
- `charter receipt <file> [--verify-tree <dir>] [--allow-same-family <decision>]` — validates a `charter.receipt/1` receipt (a pre-rename legacy receipt id is still accepted as an alias); accepted verdicts require no critical/high defect, every proof reopened and marked, frozen-bytes citation, and a verifier model family different from the author's, where a model the family table does not know is judged by the maker the receipt states for it; a model id may end in one parenthesised comment, which is never read, and an id that is otherwise not a model id, or starts with a one-letter seat prefix such as `R/`, is refused with no owner lift (a seat label belongs in the entry's `seat`, and no `seat` may be both an author and a verifier); with `models.authors` and `models.verifiers`, one model may not be listed with two makers, and every verifier is judged against every author, and a `review_families_required` of 3 or more needs that many minus one verifier families independent of every author, a shortfall `--allow-same-family` does not lift; a `charter.seat-evidence/1` record attached to a verifier (`models.verifier_evidence`, or the `evidence` of its `models.verifiers` entry) must be well formed and show no turn on a model outside that verifier's family; a Claude Code subagent's own transcript gives a record marked `"scope": "subagent"`; with `[verification_budget] seat_evidence = "required"` every judged verifier must carry such a record, except for a slice whose `charter/.dispatch/<slice>.json` already records it accepted with this receipt (or with no receipt hash); `charter receipt` compares a cited `dispatch` block with `charter/.dispatch/<slice>.json` when that record exists, and says so in a note when it does not; `gate --accept` and `gate --verify --receipt` require the record; each reads the record of the slice it judges — the DONE list the receipt resolves to for `charter receipt`, the gated slice for `gate`, the landing slice at the merge for `land-check`.
- `charter seat-evidence --harness <pi|claude-code|grok> --session <file>` — prints the session's `charter.seat-evidence/1` record; reads the file once and writes nothing.
- `charter done-count [--json]` — writes nothing; for every `charter/DONE/*.md`, sorted by path, the number of proofs and their ids as the proof parser `gate --dispatch`, `check --strict` and `charter receipt` share finds them, zero included; `--json` prints one `charter.done-count/1` object naming the build's commit.
- `charter status [--json]` — writes nothing; for every slice with a proof list or a dispatch record, sorted by id: its status from the records and git (`undispatched`, `dispatched`, `frozen`, `accepted`, or `landed` once the commit that accepted it is on the default branch), whether its proof list still matches the dispatched hash, and the authors and reviewers its accepted receipt names. A slice's status is never written into its proof list.
- `charter loops audit` — trips vs bounds, with the ledger's totals.
- `charter cost add|show` — the cost ledger.
- `charter brief <role> [slice]` — a role contract with the charter embedded.
- `charter init [--from <dir>] [--intent-file <file>] [--project <name>] [--checklist] [--refresh-spec]` — scaffold; `--checklist` prints the adoption steps; `--refresh-spec` replaces a known earlier spec text in `charter/SPEC.md` with this binary's and refuses an edited one, installs `charter/GOVERNANCE.md` and `charter/schemas/charter-toml.schema.json` when absent, replaces either when it holds a text charter published earlier, and refuses any other copy, writing nothing when it refuses.
- `charter repin [--commit]` — moves the repository at `--root` to the commit this binary was built from: installs the hooks, refreshes a known earlier `charter/SPEC.md` with its two companions as `init --refresh-spec` does, writes `charter/PIN.toml`'s `commit` line, rewrites each `.github/workflows/*.yml`/`*.yaml` line matching `^(\s*)CHARTER_REV:\s*"?[0-9a-f]{40}"?\s*$` with the same indentation and quoting and every other byte kept, then runs `check --strict` and `hooks status` and exits 0 only when both pass; it refuses, before writing anything, a build whose commit is not 40 lowercase hex, a root with no `charter/`, a pin that declares `self`, and a dirty tracked tree; with `--commit` it stages the files it wrote and records them as one `charter: re-pin to <commit>` commit through the hooks it just installed.
- `charter hooks install [--force]` — pre-commit runs `check`; pre-push runs `check --strict` with the pushed refs, `gate --verify` for every dispatched slice and, when `[land_check] enforce` is set, `land-check`, and writes nothing; both run a kept foreign hook first and refuse a binary other than the build `charter/PIN.toml` declares.
- `charter sync-agents`, `charter decision new <slug>`.
- `charter hooks status` — writes nothing; names the binary each installed hook resolves and whether it is the build `charter/PIN.toml` declares; exits 1 when a hook is missing, is not charter's, or resolves a build other than the declared one, and also when no `charter/PIN.toml` declares one, when that file is invalid, when a hook resolves no binary, and when a hook carries an older charter text (a fixed path, no pin check, or no PIN.toml shape check), naming the re-install.

## What "done" means (normative)

Done is every proof in the slice's DONE list executed, its run reopened from the frozen bytes and compared, the tree frozen, the gate accepted, the STATE rewritten, and the Linux CI run on the frozen bytes green. "No findings" is never done.
